Babylon.jsを使い、ブラウザーで遊べるミニアプリ
「ORBITAL — 星を鳴らす重力工房」を、このプロジェクトに実装してください。

目標は技術デモではなく、短くても人に見せたくなる完成作品です。
機能の多さより、美術・操作・音・遊びの一貫性を優先してください。
今回はデスクトップブラウザーを主対象にします。

【体験】
真鍮と陶器でできた小さな天体装置で、重力レンズを配置し、
放った星を3つの共鳴リングへ順番に通し、最後に受け皿へ導く。

1回の軌道は最大12秒。
レンズはステージごとに1〜3個。位置だけを調整でき、強さは固定。
操作は盤面内のドラッグに限定する。

編集時には予測軌道を表示する。
再生中は配置を固定し、リング通過時に音・振動・光の波紋を同期させる。
失敗してもすぐ調整して再挑戦でき、直前の軌跡を薄く残す。

時間バーで直前の走行をスクラブできる。
これは状態記録の再生として実装し、逆向きの物理計算はしない。
配置を変えたら開始時点から再計算する。途中状態からの分岐は不要。
スクラブ中には通過音を鳴らさない。

成功すると操作UIを控えめにし、完成した軌道と音をループ鑑賞できる。
必ず成立する解を持つ、学習順序のある3ステージを用意する。

【美術】
深い藍色、乳白色の陶器、真鍮、アンバーの光で統一。
斜め上から見た、精密な卓上天体装置にする。
造形には厚み、面取り、台座、刻印など、近くで見ても成立する細部を入れる。

盤面には重力場を読める控えめな等高線、
星には細く美しい軌跡、リングには反応の分かるアニメーションを付ける。
光らせすぎず、素材の違いと余白を大切にする。

球と床を並べただけのデモ、過剰なネオン、大量のカードUI、
意味のない常時カメラ移動は避ける。
画面の主役は常に3Dの装置とする。

【技術方針】
Vite + TypeScript + Babylon.js + Web Audio API。
UIは必要最小限のHTML/CSSでよい。バックエンドとLLM APIは不要。
既存プロジェクトの構成がある場合は、それを尊重する。

描画はWebGL2で完成させる。WebGPU対応は完成後の追加扱い。
基本造形と音は手続き生成を中心にし、有料アセットに依存しない。
外部素材が必要なら、出典と利用条件を明記する。

星の運動は固定時間刻みの独立したシミュレーターにする。
描画フレームレートに物理結果を依存させない。
重力中心付近で発散しないようにし、
高速移動でもリングの通過を取りこぼさない判定にする。

予測線と本番は同じシミュレーション処理を使う。
描画・物理・入力・音・ステージデータ・状態遷移を分離する。
この題材では汎用の剛体物理エンジンを無理に導入しない。

レンズ操作とカメラ操作を競合させない。
キーボードでもレンズ選択・微調整・再生ができるようにする。
音は開始操作後に有効化し、常にミュート可能にする。
動きを抑える設定を尊重し、未対応環境や初期化失敗は画面で説明する。

【完成条件】
最初の画面で、何を触れるか分かる。
初回30秒以内に、操作によって軌道と音が変わる楽しさを体験できる。
予測と実走が一致し、リセット・再挑戦・タブ復帰で状態や音が壊れない。
各ステージには、成立する解の配置データを内部で保持する。

使用端末・ブラウザーを明記し、描画解像度1440×900、DPR 1で
60fpsを目標にする。未達なら、物理ではなく描画側の負荷を調整する。

まず1ステージを最後まで遊べる形にし、
同じ1ステージで美術・音・操作を磨いてから残りを展開する。
最初のもっともらしい見た目で止めず、実際に操作しながら改善する。
未完成部分を、完成したように説明しない。

# ORBITAL — 実装と起動

真鍮と乳白色の陶器でできた、ブラウザー上の小さな天体装置です。
重力レンズを動かし、星を3つの共鳴リングへ順番に通して、受け皿へ導きます。
上に保存した制作プロンプトを、このリポジトリのアプリとして実装しています。

## 起動

Node.js **22.18以降**とnpmを使用します。

```sh
npm install
npm run dev
```

**http://127.0.0.1:53147/** をデスクトップブラウザーで開いてください。
ほかのアプリの開発サーバーと競合しにくいよう、ポート53147を使用しています。
変更する場合は `npm run dev -- --port 53150` のように指定できます。

本番用の静的ファイルを生成する場合：

```sh
npm run build
npm run preview
```

`dist/` を静的ホスティングに配置できます。バックエンド、アカウント、APIキーは不要です。

## 遊び方

点線が予測軌道です。真鍮のレンズを盤面でドラッグすると、引力の等高線と軌道が変わります。
「星を放つ」で再生し、01 → 02 → 03 → 受け皿の順につないでください。
初期配置のままでも音の変化を試せます。迷ったら「ヒント」で位置の目安を表示し、
もう一度押すと「お手本を置く」で成立する配置を試せます。

| 操作 | 方法 |
| --- | --- |
| レンズの位置を調整 | 盤面のレンズをドラッグ |
| レンズを選択 | `1` / `2` / `3`、選択ボタン、またはTab |
| 位置を微調整 | 矢印キー。Shiftを併用すると、さらに細かく移動 |
| 再生・一時停止 | 再生ボタン、またはSpace |
| 配置の編集に戻る | 「配置に戻る」、またはEsc |
| 初期配置へリセット | 「初期配置」、またはR |
| ミュート | 右上の音ボタン、またはM |
| 記録をスクラブ | 走行後の時間バーをドラッグ。フォーカス中は矢印キーも使用可能 |

一般のボタンにフォーカスしているときのSpaceは、そのボタンを実行します。
レンズと時間バーにフォーカスしているときは再生・一時停止になります。
音は最初の再生操作後に有効になります。スクラブ中は音を出しません。

成功すると操作UIが控えめになり、軌道と旋律を繰り返し鑑賞できます。
「ループ」で切り替え、「次の軌道へ」で次のステージに進めます。
右上のステージ番号から直接移動することもできます。

## 3つのステージ

| ステージ | レンズ | 学ぶこと | お手本の走行時間 |
| --- | --- | --- | --- |
| I · 引力のひと筆 | 1個 | ひとつの引力で軌道を曲げる | 約5.83秒 |
| II · ふたつの釣り合い | 2個 | 引力を受け渡し、S字の軌道を作る | 約4.74秒 |
| III · 回り道の三重奏 | 3個 | 大きな弧を描き、最後の進行方向を整える | 約7.78秒 |

初期配置・固定の引力・リング・成立する解は [`src/data/stages.ts`](src/data/stages.ts) に保存しています。
最初のステージを遊べる状態にして描画・操作・音を調整してから、残りの2ステージを追加しました。

## 実装の構成

- `src/core/simulation.ts` — 固定120Hzの独立したシミュレーター。軟化した重力とvelocity Verlet法を使用します。
- `src/core/session.ts` — 編集、再生、一時停止、スクラブ、成功ループの状態遷移。
- `src/render/` — Babylon.jsによるWebGL 2描画、面取りした造形、手続きテクスチャ、等高線、軌跡。
- `src/input/controls.ts` — ドラッグ、ポインターキャプチャ、キーボード入力。カメラは固定です。
- `src/audio/instrument.ts` — Web Audioの倍音合成、定位、手続き生成の残響、ミュート。
- `src/ui/view.ts` / `src/styles.css` — HTML/CSSの操作UI、案内、設定、狭い画面への調整。

予測と実走には**同じシミュレーション結果**を使用します。開始時に前向きの計算で全サンプルと
通過イベントを記録し、描画はその時刻を参照します。逆向きの物理計算や、途中状態からの分岐はありません。
配置を変えると開始位置から計算し直し、時間バーをリセットします。直前の軌跡は薄く残ります。
高速の星は、移動区間とリングの開口面・受け皿の交差で判定し、同じ刻み内の通過も時刻順に処理します。

レンズ付近でも重力が発散しないようにしています。描画のフレームレート、品質設定、画面サイズは
物理結果を変えません。汎用の剛体物理エンジンは使用していません。

## アクセシビリティと中断

OSの `prefers-reduced-motion` と、遊び方パネルの「動きを控えめにする」に対応しています。
控えめな設定ではリングの振動・波紋と自動ループを抑え、ゲームに必要な星の移動は残します。
再生中はレンズの配置を固定します。

非表示への切り替え、長い描画中断の検知、WebGLコンテキスト喪失時には時間と音を止めます。
復帰後は操作によって再開し、たまった通過音をまとめて鳴らしません。
WebGL 2の初期化失敗は画面で説明し、音を利用できない場合も理由を表示してミュートで続行できます。

## 確認と計測

```sh
npm test
npm run build
npm exec playwright install chromium  # ブラウザーが未導入の場合のみ
npm run test:e2e
npm run benchmark
```

`benchmark` は本番ビルドを空きポートで起動して計測し、そのサーバーを終了時に閉じます。
計測結果と各ステージの画像は `test-results/benchmark/` に保存します。

ユニットテストはNode.js標準のテストランナーを使用します。
保存した全ステージの解、固定刻み、重力中心の安定性、高速通過、リングの順序、
予測と実走の一致、スクラブ、リセット、実際に描ける点線を確認しています。

ブラウザーテストでは実際のマウスドラッグ・キー入力で全ステージを完成させ、
音声出力の振幅とミュート、無音スクラブ、リサイズ、生成リソースの解放、
WebGLコンテキストの喪失／復元、音声未対応時の案内を確認しています。
非表示／復帰については、headlessブラウザーがタブ切り替えで非表示にならないため、
Page Visibility APIの状態とイベントを再現して確認しています。

**計測環境（2026-09-14）**：Apple M5 Max、メモリ64GB、macOS 26.6.2、
Chromium 153.0.8010.12（Playwrightの新headlessモード、ANGLE Metalの実GPU）。
本番ビルド、描画解像度 **1440×900**、**DPR 1**、通常描画品質で、
各ステージの再生・ループ中にウォームアップ後の600フレーム間隔を計測しました。

| ステージ | 平均fps | 平均フレーム間隔 | 95パーセンタイル |
| --- | --- | --- | --- |
| I | 60.00 | 16.666ms | 16.8ms |
| II | 60.00 | 16.666ms | 16.7ms |
| III | 60.00 | 16.666ms | 16.7ms |

これは `requestAnimationFrame` の間隔の計測であり、GPU単体の処理時間ではありません。
上記環境で60fpsの目標を確認しましたが、ほかの端末、Firefox、Safariの実機では未計測です。
描画が継続的に遅い場合は影を省略して描画負荷を下げます。物理計算や記録は変更しません。
実行中のfps・解像度・描画環境は、右上の「?」内でも確認できます。

主対象はデスクトップです。WebGPUは実装対象に含めていません。
外部の画像・音声・3Dモデル・Webフォント、有料アセットは使用していません。
造形、刻印、重力場、星の軌跡、音、残響はコードから生成しています。
